## 2025-02-14 - Truthy Empty Arrays in node-postgres & Missing Input Validation
**Vulnerability:** Under validation of `email` and `cpf` fields allows storing malformed data in the database. Furthermore, in existing controller endpoints, a database query returning no matching rows returns an empty array `[]` (truthy in JavaScript). Standard checks like `if (!updated)` failed to detect "not found" conditions, leading to returning `[]` status code responses as if the resource was successfully found and updated/deleted.
**Learning:** In Javascript, empty arrays `[]` are truthy objects. When using `node-postgres` or model methods that return query result arrays directly, a return check needs to verify both that the result is truthy AND that it has a non-zero length: `if (!updated || updated.length === 0)`.
**Prevention:** Always write check conditions as `if (!result || result.length === 0)` when validating returned rows from database helpers in order to correctly trigger 404 Not Found error states, and implement structured input validation utilities using rigid regular expressions (e.g. `isValidEmail` and `isValidCPF`) on API request payloads.
